# Карта d.java (декомпилят J2ME-игры) — шаг 1 порта

Файл: `tools/decompiled_java/d.java`, 11 485 строк, 295 методов. Экран 240×320 (портрет).
Пометки: **[код]** — прочитано в коде, **[гипотеза]** — вывод, надо проверить.

## 1. Каркас
- `d extends GameCanvas implements Runnable` — главный класс; `mygame` (MIDlet) только создаёт `d` и вызывает `m()/n()/o()` (старт/пауза/выход). **[код]**
- `run()` (стр. 1882): бесконечный цикл `while (T >= 0)`: вызывает `p()` (кадр: `a(Graphics)` → `ac()` + `flushGraphics`), потом ждёт, пока с начала кадра не пройдёт **100 мс** (`T != 2`). Итог: логика и отрисовка идут вместе, **~10 кадров/с**, шага по времени нет. **[код]**
- Для веба: `setInterval`/`requestAnimationFrame` с накоплением до 100 мс, один вызов «тика» за шаг; всё, что в оригинале зависит от кадра (скорости, таймеры), считать в тиках, а не в миллисекундах.

## 2. Ввод
- `keyPressed/keyReleased` пишут в `ao[0..14]` счётчик удержания (>0 — нажата, <0 — только что отпущена); `q()` в начале кадра копирует его в `an[]` и увеличивает. **[код]**
- Раскладка (`w(int)`, стр. 1997–2090): клавиши 0–9 → коды 1–10, `*` → 11, `#` → 12, левая/правая софт-клавиши (-7/-6) → 13/14; стрелки через `getGameAction`: вверх → 3, влево → 5, вправо → 7, вниз → 9, центр → 6. Т.е. цифры 2/4/6/8/5 дублируют стрелки. **[код]**
- Для веба: таблица `KeyboardEvent.code → индекс 0..14`, те же счётчики.

## 3. Машина состояний (`T`), диспетчер `ac()` (стр. 964)
`T` меняется через `t(n)`; `Y` и `Z` — подшаг и подпункт внутри состояния. **[код]**

| T | Метод | Что делает (по началу кода/строкам) |
|---|-------|-------------------------------------|
| -1 | `h(true)`, `by()` | выход, освобождение ресурсов |
| 0 | `t(1)` | переход на старт |
| 1 | `ad()` | загрузка, заставка (`/t`) |
| 2 | `ae()` | загрузка уровня (карта, `b.A`), `gc` |
| 3 | `af()` | меню из 2 пунктов (мигание по `au & 8`) **[гипотеза: выбор звука]** |
| 4 | `ag()` | экран с картинкой и градиентом, ждёт клавишу |
| 5 | `ak()` | главное меню |
| 6 | `ao()` | пауза/внутриигровое меню |
| 7 | `at()` | **основной игровой тик** (см. ниже) |
| 8 | `aU()` | экран миссий/диалогов (`switch (cu)`, таблицы `dk`, `ds`) **[гипотеза]** |
| 9 | `ah()` | экран результатов/статистики |
| 10 | `aj()` | карта города (мини-карта из тайлов, `fR/fS` — масштаб) |
| 11 | `ai()` | текстовый экран (строки `ex`, постраничный вывод по 12) |
| 12, 13 | `an()` | «О программе»/настройки (читает `MIDlet-Version`) |
| 14 | `v()` | вспомогательный экран с 4 кнопками |
| 15 | `t()` | отдельный экран (74 строки) |

Звук: `r(n)` ставит трек в очередь, `g()` проигрывает: треки `n < 19` — MIDI (`n_00…n_18`), `n ≥ 19` — WAV (`n_19…n_23`); трек 9 зациклен. Это совпадает с `assets/midi` и `assets/wav`. **[код]**

## 4. Игровой тик `at()` (стр. 3677–3940), порядок вызовов
Порядок важен — его надо повторить 1:1. **[код]**
1. Служебное: счётчики кадров `bD/bE/bF`, `ay()`, `aB()`, пауза `bQ`.
2. `P()`, `aw()`, затем ввод и управление игроком `bA()`; камера: `bI = -fU`, `bJ = -fV + 18`.
3. Обновление мира: `bq()`, `b.y()`, `bb()`, `aD()`, `cd.w()` и `cd.a(ff[0], true, false)` (коллизии игрока), `bo()`.
4. Отрисовка: `d.b(am)` (карта), `bp()`, `be()`, цикл по 4 слотам `cN[]` (`f(...)`).
5. Слои сущностей: `X(0)`, `X(1)`, затем `b.B()` и `X(2)`: `X(n)` обходит связный список сущностей слоя `n` (`hk/hm/hn`) и вызывает у каждой `g()` (обновление+отрисовка).
6. HUD и поверх: `ax()`, `aP()`, `H()/G()/J()`, `az()`, `aa()`, `d(am)`.

## 5. Сущности: класс `b` (4127 строк)
- `b` — единая сущность мира: игрок (`d.cd`), машины, пешеходы и т.д. Поля: `a,b` — позиция (**фиксированная точка 8 бит**, `>> 8` даёт пиксели), `c,d` — скорость, `h` — скорость вдоль направления, `k` — угол, `e` — битовые флаги состояния (напр. `0x200000` — упёрся в стену, `0x40000/0x80000` — столкновение по X/Y), `i[19]` и `j[10]` — типы/параметры. **[код + частично гипотеза по смыслу полей]**
- `g()` — обновление и отрисовка сущности; `a(b, boolean, boolean)` (стр. 3717, 229 строк) — движение с коллизиями: 4 угла хитбокса через `d.t(x,y)`, при значении 2 — выталкивание из стены и обнуление скорости. **[код]**
- Крупные методы `b`: `e(int,b)`, `N()`, `C()`, `c()`, `O()`, `R()`, `M()`, `u()` — по 120–200 строк, это, вероятно, поведения по типам (ИИ машин, пешеходы, оружие). **[гипотеза]**
- Классы `a` (спрайты/анимации, 875 строк) и `c` (проигрыватель анимации: кадр `e`, тик `f`) в основном уже покрыты `engine.js`.

## 6. Коллизии

- Остальное (0 — дорога, 1 — тротуар, 3 — зона у входа) — по картинке, **[гипотеза]**.

## 8. Спавн сущностей (разведка, `bq()` стр. 9318)
- `bq()` вызывается каждый тик: два таймера (`hd`, `he`), по истечении которых делается до 3 попыток спавна: `br()` каждые 0.5–1 с и `bs()` каждые 0.3–1.3 с. **[код]**
- `br()` спавнит **пешехода** (`d.M(2)` = слой 2, тип `b.i[0]=8`) со спрайтом `bB[2]` — тем же, что и у игрока (`cd.a((byte)4, …, bB[2], …)`). Это подтверждает, что игрок и прохожие рисуются одним спрайтом (`i_00`). **[код]**
- Точки спавна: `bh[зона]` — плоский массив по 5 значений на точку; зон 4, они вокруг камеры (`cL[]`, `cN[]`; `Q()/R()` переводят номер ячейки в пиксели). Точка подходит, если она вне экрана и не дальше `k[2]*24` (`n4`), и проходит проверку `d.v(...)`. Лимит: `fi - fg[2]` (максимум − уже есть). **[код]**
- Параметры пешехода в `d.a(b, x, y, bl, n3)` (стр. 9396): случайный облик (`n4` 0/1/2), тип поведения `i[3]` по таблицам `g[]`/`h[]` (доли «обычный/агрессивный» и т.п.), иногда оружие/реплики `i[8]`. **[код]**
- `bs()` (стр. 9442) — по структуре второй спавнер (вероятно, машины); ещё не читал. **[гипотеза]**
- План: сначала пешеходы (спавн по `bh`, ходьба по тротуарам — коллизия 1, слои `X(n)`), потом машины.

## 9. Пешеходы: что подтверждено и реализовано (`js/peds.js`)
- Данные: ресурс уровня `f` (город 1) / `u` (город 2), разбор `d.U(int)`: поток групп «тип, число, полей, значения int16 LE» по типам блоков. Тип 9 = узлы маршрутов пешеходов `bh[типБлока]`: x, y (px внутри блока), ссылки E/N и W/S (по байту), маска разрешённых направлений. Все 137/117 узлов лежат на тайлах с коллизией 1. **[код + проверено]**
- Тип 0 = полосы машин `aY` (7 значений), тип 1 = `aZ` (5 значений, миссии/триггеры) — извлечены в `raw`, ещё не разобраны.
- ИИ: каждые 200 мс (`l >= 200`); продольная скорость по `g()` (макс. 768/512, разгон 85), поперечная подстройка к линии узла (`d.d*16/24` = 218), прибытие по `J()`, выбор следующего узла по маске и таблице `z` (из `e_00`, объект 13), переход в соседний блок через `c(n,n2,n3)`. **[код]**
- Анимации: `120 + вид*44 + (dir>>2)*11 + {0 стоит, 1 шаг, 2 быстро}`; вид 2 — `208 + (dir>>2)*5 + …`. Палитра `1..3`. **[код]**
